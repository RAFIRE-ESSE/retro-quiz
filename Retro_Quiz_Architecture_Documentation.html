Deterministic Scoring Algorithm

EARNED_POINTS = Math.round((100 + SPEED_BONUS) * STREAK_MULTIPLIER)

Base Points +100 PTS per correct answer All Modes (Standard, Blitz, Practice, Sudden Death)

State Synchronization & Closure Prevention Architecture

In standard React state updates, calling asynchronous delays like setTimeout on the final question captures stale closure states, causing lost points on the results screen. The engine enforces Synchronous Mutable References: 

// Synchronous Engine State in app/quiz/[id]/page.tsx
const scoreRef = useRef(0);
const streakRef = useRef(0);
const maxStreakRef = useRef(0);
const answersLogRef = useRef<AnswerLogItem[]>([]);
const totalTimeSpentRef = useRef(0);

// Answer Evaluation Execution (Synchronous Mutation)
const handleAnswerSelect = (optionIndex: number) => {
  if (isAnswerSubmitted) return;
  const isCorrect = optionIndex === currentQ.correctOption;
  if (isCorrect) {
    streakRef.current += 1;
    if (streakRef.current > maxStreakRef.current) maxStreakRef.current = streakRef.current;
    const earned = Math.round((100 + timeBonus) * multiplier);
    scoreRef.current += earned;
  } else {
    streakRef.current = 0;
  }
  answersLogRef.current.push(logEntry);
  setScore(scoreRef.current); // React state updated exclusively for visual HUD
};

3. CLOUD DATABASE & API SPECIFICATION

Neon PostgreSQL Normalized Schema

-- Quizzes Metadata Table
CREATE TABLE IF NOT EXISTS quizzes (
  id SERIAL PRIMARY KEY,
  slug VARCHAR(100) UNIQUE NOT NULL,
  title VARCHAR(200) NOT NULL,
  description TEXT NOT NULL,
  category VARCHAR(50) NOT NULL,
  icon VARCHAR(10) DEFAULT '🕹️',
  difficulty VARCHAR(20) DEFAULT 'medium',
  is_custom BOOLEAN DEFAULT false,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- Questions Relational Child Table
CREATE TABLE IF NOT EXISTS questions (
  id SERIAL PRIMARY KEY,
  quiz_id INT NOT NULL REFERENCES quizzes(id) ON DELETE CASCADE,
  question_text TEXT NOT NULL,
  code_snippet TEXT,
  option_a TEXT NOT NULL, option_b TEXT NOT NULL, option_c TEXT NOT NULL, option_d TEXT NOT NULL,
  correct_option INT NOT NULL CHECK (correct_option BETWEEN 0 AND 3),
  explanation TEXT NOT NULL, difficulty VARCHAR(20) DEFAULT 'medium'
);

-- Leaderboard High Scores Table
CREATE TABLE IF NOT EXISTS scores (
  id SERIAL PRIMARY KEY, quiz_id INT, quiz_title VARCHAR(200), gamer_tag VARCHAR(50) NOT NULL,
  score INT NOT NULL, accuracy INT NOT NULL, max_streak INT DEFAULT 0, game_mode VARCHAR(30) DEFAULT 'standard',
  time_spent_seconds INT DEFAULT 0, played_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

Leaderboard Query with LEFT JOIN Resilience

SELECT s.id, s.quiz_id AS "quizId", COALESCE(q.title, s.quiz_title, 'Retro Cartridge') AS "quizTitle",
       s.gamer_tag AS "gamerTag", s.score, s.accuracy, s.max_streak AS "maxStreak",
       s.game_mode AS "gameMode", s.time_spent_seconds AS "timeSpentSeconds", s.played_at AS "playedAt"
FROM scores s LEFT JOIN quizzes q ON s.quiz_id = q.id ORDER BY s.score DESC, s.played_at DESC LIMIT 50;

4. DEPLOYMENT & RUNTIME OPERATIONS

Automated CI/CD Pipeline (GitHub → Vercel → Neon)

  1. Git Push: Commit pushed to https://github.com/RAFIRE-ESSE/retro-quiz.git.
  2. Vercel Build: Webhook executes npm run build, running Next.js static tree-shaking and route compilation.
  3. Edge Execution: Serverless Route Handlers are provisioned in AWS us-east-1 data centers.
  4. Database Link: App reads DATABASE_URL and connects via @neondatabase/serverless over pooled HTTPS transport.
  5. Self-Healing Initialization: If database tables are fresh, initNeonDatabase() automatically creates all schemas and seeds the initial cartridges.
